# FOCの角度予測補正（2026-10-17）

## 補正時刻と座標系

FOCの電圧出力角は、**次のPWM更新時刻からさらに半周期先**、つまり次のPWM区間の中央時刻に向けて予測する。20 kHz制御での時刻関係は次のとおり。

```
現在の頂点／ADCトリガ付近    次の頂点／CCR反映    予測の目標時刻
0 µs                        50 µs               75 µs
```

`AS5047P_Sample.reference_cycles`には、**要求フレーム末尾のCS立ち上がり時刻**を記録する。GPIO書き込み完了直後にDWTを読み取り、CS操作から時刻取得までを短い割り込み禁止区間で保護する。この要求に対応する読み出し値は、次のNOPフレームで返される。`request_cycles`と`received_cycles`は従来の診断用の意味を維持する。サンプル構造体は32バイトから36バイトに拡張したが、この構造体は通信プロトコルの形式ではない。

AS5047PがCS立ち上がりでSPI読み出し値を確定する仕様は、メーカーの[データシート13ページ「SPI Read Data Frame」](https://www.mouser.com/datasheet/2/588/AS5047P_DS000324_2-00-1843440.pdf)に記載されている。
本実装は、既存のセンサー設定がDAECDIS=0、Dataselect=0であり、ANGLECOM（0x3FFF）からDAEC補正済み角度が返ることを前提とする。センサー設定やOTPは変更しない。未補正の内部伝搬遅延や、ABI/UVW向けの残留遅延を追加する補正は行わない。

センサーの基準時刻における角度に、回転方向、極対数、オフセット、および有効時のH2空間補正を適用する。α–βオブザーバーでこの補正済み電気角を追跡するため、推定角速度にも校正方向の符号とH2補正の影響が含まれる。新しいシーケンスのサンプルごとに、次の計算を行う。

```
dt = unsigned(reference_cycles - previous_reference_cycles) / SystemCoreClock
g = dt / (tau + dt)
alpha = 2*g - g*g
beta = g*g
predicted = previous_angle + velocity*dt
error = shortest_angle(measurement - predicted)
angle = wrap(predicted + alpha*error)
velocity += beta*error/dt
```

`shortest_angle`は周回を考慮した最短方向の角度差、`wrap`は角度の範囲内への折り返しを表す。

`MOTOR_CONTROL_FOC_TRACKING_TAU_S`の初期値は0.5 ms。同じシーケンスのサンプルでオブザーバーを重複更新せず、電流用・PWM用の両予測を同じ基準から求める。起動時とH2設定変更時には、推定速度をゼロにしてオブザーバーを初期化する。既存の機械回転数（RPM）監視は独立して維持し、そのサンプル間隔にはCS基準時刻の差を使用する。

Park変換には`wrap(angle + velocity*(t_adc-t_reference))`、逆Park変換には`wrap(angle + velocity*(t_pwm_midpoint-t_reference))`を使用する。そのADC周期では同じスナップショットとオブザーバー状態を使い、演算遅延を別項目として加算することはしない。

## タイマとADCの前提

`MotorControl_FocAdcBeginISR`は、TIM1のCNT/DIRと、その読み取り前後のDWT時刻を取得する。取得中にカウント方向が変わった場合は再取得し、現在の頂点からの位相を求める。締切計測用には、従来のコールバック開始時刻を別に保持する。`MotorControl_GetFocTimesISR`は、この位相と初期化時の制御周波数から頂点時刻を求め、1.5周期を加えてPWMの予測目標時刻とする。既存のプリロード書き込み締切監視を維持し、締切に遅れた場合はFOCを停止する。

ADCの代表サンプル時刻は、CC4トリガの625 ns後とする。これは40 MHzのADCクロックで、2つのサンプルホールド終了時刻（12.5クロック後と37.5クロック後）の平均に相当する。設定値は`MOTOR_CONTROL_FOC_ADC_SAMPLE_OFFSET_NS`。ADCクロック、ランク構成、分解能、サンプリング時間を変更した場合は見直す必要がある。U1/U2、V、Wに対する代表時刻であり、すべての相電流が同時にサンプリングされたことを意味しない。

サブマイクロ秒の精度を評価するには、ADCトリガの同期遅延、アナログ経路の遅延、ソフトウェアによるタイムスタンプの数クロック程度の不確かさを実機で確認する必要がある。今回の変更では、これらの影響やトランジスタのデッドタイムは補正しない。

角度の鮮度監視は、通信処理開始時刻ではなく、角度値が確定するCS立ち上がりの`reference_cycles`を基準とする。上限250 µsは維持し、予測によって古いサンプルを新しいものとして扱うことはない。オブザーバーへの入力・更新間隔・予測時間が不正な場合はFOCを停止する。時刻差分はuint32のDWT周回に対応し、予測用の符号付き時間差によって、センサー読み出しがADCサンプル時刻よりわずかに後になった場合も扱う。

## 診断表示とログ

`foc status`に`FOC prediction`行を追加した。ADC/PWMへの外挿時間をns、電気角速度をmrad/s、Park用とPWM用の角度をそれぞれmradで表示する。既存の`elec`表示は、PWM区間中央の予測角度を示す。

ADCログの`elec_rad`は引き続きPark変換に使用した角度とし、次の項目を追加した。

- `pwm_elec_rad`：次のPWM区間中央を目標とする逆Park変換用の角度。
- `omega_e_rad_s`：符号付きの推定電気角速度。
- `angle_adc_dt_us`、`angle_pwm_dt_us`：CS基準時刻から各目標時刻までの符号付き時間差。

`elec_base_rad`と`elec_corr_rad`は、引き続きセンサーの生角度の基準時刻における空間補正値を示す。その和は、予測後の最終的なPark角度とは一致しなくなる。ログ項目の追加でUART通信量が増えるため、間引き率を選ぶ際は`log_overrun`を確認する。

## 実機試験と追加修正（2026-10-17）

COM6／921600 baud、約24.2 V、既存の負荷と保存済み校正で検証した。ログは`build/prediction_hw_20261017/`。校正領域を退避し、各書き込みのVerifyを確認した。電流・速度・角度鮮度・PWM締切の保護しきい値は変更していない。

初回0.5 A試験では`encoder age limit`が発生した。予測計算の追加でSPIの処理余裕が減り、通信開始から角度値確定までの待ちも鮮度に算入していたため、次を修正した。

1. オブザーバーの角度正規化に、通常範囲を加減算で処理する経路を追加した。大きい入力には従来の`fmodf`を残す。
2. 予測と鮮度監視の基準をCS立ち上がり時刻に統一した。250 µsの上限は維持した。
3. 続くH2 ON＋ADCログ試験で`PWM update deadline`が発生したため、`current_sense.c`の処理順をPWM計算・CCR書き込み→ログコピーへ変更した。同じADC周期の観測値を記録する点は維持する。

### CANと検証範囲

COM13のUSB-CANは、ポートOpen時にWindowsから「A device attached to the system is not functioning」が返り、一覧から消える状態も確認した。通常実行とアクセス権を切り分けた再試行でも開けず、CAN試験はPWM開始前に中断した。今回の回転試験はUART指令によるものであり、USB-CAN経由の指令・通信途絶停止は未検証。最終Debug／Releaseの`test_can_foc.py`によるモデル試験は合格した。

### 評価

**今回の約100～110 rpm・5 Aでは、補正による明確な改善を検出できなかった。効果がないと証明したわけではない。**

- 2回ずつの試行平均で、Iq標準偏差は正転67.16→66.11 mA、逆転69.33→67.35 mAとわずかに小さくなった。しかしOFF同士でも約4～5 mAの差があり、補正効果と区別できない。各方向・各モード2試行なので、統計的な優位性は主張しない。
- 相電流RMSのON/OFF差は正転約+0.03%、逆転約+0.11%で、電流低減は確認できなかった。同一Iq指令の試験なので、同一軸トルクに必要な電流を測る試験でもない。
- 必要電圧は正転で平均約0.5%低下した一方、逆転では約1.4%増加した。状態表示の速度を5 rpm刻みで絞っても正逆で傾向が一致しないため、効率改善の根拠にはしない。
- ON時のセンサー基準時刻からPWM目標までの推定前進角は平均約0.54～0.58電気角度。この運転域では小さく、試行間変動に埋もれる可能性がある。AS5047Pの内部DAEC遅れは追加していない。
- ADC制御区間の最大は全試行で38.037～38.456 µs。ログoverrunは全試行0。OFFでもオブザーバーと予測計算経路を残しているので、この比較から実装全体の計算コストは求められない。

判断として、時間整合を取るための補正として実装を保持する意義はあるが、今回の低速運転の性能改善を理由に必須とは言えない。効果を明確にするには、より高速で同一速度・同一負荷を保った比較、または軸トルクと入力電力の独立計測が必要。今回は既存負荷のまま低速で比較し、それらは実施していない。
