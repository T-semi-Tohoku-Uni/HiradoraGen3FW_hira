# 電流・角度の時刻対応（2026-09-25）

ADC周期で角度を一度だけ取得し、同じ角度をPark変換と電圧計算に使う構成へ変更しました。
ソフトウェア上の時刻差をログへ追加し、Release実機で正逆それぞれ約34秒の200 Hz記録を確認しました。
センサー内部遅延の補償、角度外挿、電流PI制御は実装していません。

## 修正前後

修正前はCurrentISRのPark変換が前回TickISRの`electrical`を参照し、その後のTickISRで角度を取り直して電圧計算していました。
このため、電流の座標変換には通常さらに1制御周期前の角度が使われていました。

修正後は以下の順です。

1. ADCコールバック入口でDWT時刻を保存し、同じADC番号のU1/V/U2/Wを読む。
2. 電流保護を行い、最新の有効なAS5047P角度スナップショットを一度取得。要求開始時刻による鮮度を確認。
3. その角度を校正済み電気角に変換してId/Iqを計算。
4. 間引き対象なら相電流・Id/Iq・角度と時刻情報を同じログ点へ保存。
5. TickISRは同じ角度スナップショットを使用して速度・鮮度を確認し、電圧を計算。
6. CCR preloadを更新し、次回用のSPI取得を開始。PWMへの反映は従来どおり次の頂点。

これによりソフトウェア上の余分な1周期遅れと、同一周期内の角度データの不一致を取り除きました。
「電流と角度が物理的に同時測定になった」という意味ではありません。
起動準備中は電流保護を継続し、運転開始まで有効なdq観測を公開しません。
鮮度チェックと独立TIM監視は維持しています。

## 観測データと時刻の意味

`FocVoltage_Observation`にId/Iq/電気角に加え、ADC番号、角度更新番号、
ADCコールバック時刻、角度要求開始時刻、応答解析開始時刻を保持します。
取得APIは同じADC ISR内専用です。mainから随時読むための同期APIではありません。
将来のPIでは、このADC周期の観測値を利用できます。

ログの追加項目は次の2つです（同じADC取得番号に基づく表示時刻を付与）。

| 項目 | 定義 |
|---|---|
| `angle_age_us` | ADCコールバック入口 − SPI角度要求の開始処理時刻 |
| `angle_rx_age_us` | ADCコールバック入口 − SPI応答のソフトウェア解析開始時刻 |

単位µs、µs未満切捨て。内部はDWTの32 bit差分で計算し、周回に対応します。
後者の元になる`received_cycles`はSPI最終エッジではなく、既存のDecode処理入口の時刻です。
ADCコールバックはサンプルホールド・変換・割り込み待ちの後に呼ばれます。
センサー内部での磁気角測定時刻も取得していないため、この値を真の角度測定遅延として外挿に使用してはいけません。

U1/VとU2/Wは異なるランクで、完全同時測定ではありません。ランクごとの厳密な測定時刻は今回推定していません。
PWM反映はさらに次の頂点であり、測定角と出力時点の角度の差も残ります。
参考として7極対・600 rpmで50 µsは電気角1.26度に相当しますが、実際の必要補償量はこの1周期分だけではありません。

## ロガーの処理負荷

初回は時間差2項目をsnprintfで追加すると、正転ログで858点のoverrunが発生しました。
そのためTeleplot専用の境界確認付き整数出力へ変更し、時刻文字列を1点につき一度だけ組み立てます。
%fもsnprintfもロガーでは使用せず、文字列整形はmainのみで行います。
既存キー・符号・小数3桁・LF区切りを維持し、バッファ不足は切詰めずoverrunとして扱います。
送信文字列バッファ640 B、Release全体RAM 14,760 B / 32 KB、Flash 90,236 B / 126 KB。

## 修正後のRelease実機試験

Vd=0、Vq=±0.4 V、24 V系電源、通常電流保護10 A、極性−1、921600 bps、`adc 100`。
途中で`foc status`も取得。各方向のログ取得幅はDWTの約26.8秒周回を超えています。

| 項目 | 正転 | 逆転 |
|---|---:|---:|
| ログ点数 | 6,826 | 6,839 |
| ログ取得時刻幅 [ms] | 34,116.127 | 34,181.111 |
| 算出レート [Hz] | 200.052 | 200.052 |
| 要求開始基準age 最小/中央値/95%/最大 [µs] | 73 / 74 / 74 / 175 | 73 / 74 / 74 / 174 |
| 応答解析基準age 最小/中央値/95%/最大 [µs] | 21 / 22 / 55 / 155 | 21 / 22 / 55 / 155 |
| FOC演算最大 [µs] | 10.987 | 10.987 |
| ADC制御処理最大 [µs] | 25.468 | 25.462 |
| 制御側の角度age最大 [µs] | 237.475 | 237.475 |
| SPI取得要求見送り（起動以来累積） | 780 | 1,574 |

- 全10個の時刻付き項目の点数・時刻が一致。sample差はすべて100、log_overrun全点0。
- 全点で0 ≤ 応答解析基準age ≤ 要求開始基準age ≤ 250 µs。
- 相電流と角度からId/Iqを再計算した誤差RMSは約0.0004 A（表示丸めと整合）。
- UART errors/overrun/queue_drops/flagsは0。encoder spi/parity/sensor/timeoutも0。保護停止なし。
- 非FOCではId/Iq・角度・時間差項目を出さないことを確認。
- Release/Debugビルド成功。実機はReleaseのみ。CubeMX変更なし。

`compute_max`が短くなった主因には、角度取得・校正変換をCurrentISRへ移したことが含まれます。
全体が同じだけ高速化したとは解釈しないでください。ADC制御処理の最大時間も併記しています。
制御側age最大値は起動中を含む全周期のTickISR時刻基準、ログ値は間引いたADCコールバック時刻基準で、直接一致しません。

取得要求見送りは合計1,574回と前回より増えました。今回の約145万制御周期に対し約0.11%ですが、
取得遅延や診断によって同じ角度を複数周期使う場合があります。250 µs制限に対する最大値の余裕は約12.5 µsです。
電流PI追加前には、センサー内部遅延・ADCランク時刻・PWM反映時刻と併せて時間余裕を検討する必要があります。
本試験では長時間耐久性や高負荷・高回転条件まで確認していません。
