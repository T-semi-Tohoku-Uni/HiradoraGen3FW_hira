# FOC開始時にTIM1の位相をTIM8へ合わせる設計

状態: 開始時位相合わせを実装し、正逆30秒・再始動10回・10分連続運転の検証を完了。
[実装内容と検証記録](encoder_phase_validation_2026-10-08.md)を参照。

## 採用する構成

TIM8は現在の50 µs循環DMAをそのまま連続運転する。
FOCを開始する際、TIM8の位相を見てTIM1を頂点・下降開始で起動する。
両方が同一160 MHzクロックの8000 tick周期なので、途中で停止・設定変更されなければ
開始時に決めた位相差を維持できる。これは開始時の位相合わせであり、毎周期のハードウェア再同期ではない。

前案のTIM1 TRGO→TIM8 Resetよりこちらを先に評価する。
理由は、TIM1のUGや停止のたびにTIM8通信を止め、応答対応と時刻基準を作り直す変更を避けられるため。
50 µs追試で各運転中の位相が安定する方向の結果が得られたことも、この選択の根拠。
長時間・全周期での位相維持は未検証なので、採用前に確認する。

中央揃えの周期は2*ARR tick、上向きはARR+1 tick。
[STのカウント方式の説明](https://wiki.st.com/stm32mcu/wiki/Getting_started_with_TIM)。

## 固定する設定

| 項目 | 使用値 |
|---|---|
| TIM1 | PSC=0、ARR=4000、Center Aligned 1、RCR=1 |
| ADC起動 | 既存TIM1 CH4、CCR4=3999 |
| TIM8 | PSC=0、ARR=7999、Up、Slave無効 |
| CS | 既存CH1 PWM1、CCR1=6400（TIM8周期開始から40 µs） |
| SPI送信要求 | 既存CH2、CCR2=6560（同41 µs） |
| SPI/RX/TX DMA | 現状維持。16 bit/5 MHz、1フレーム/50 µs |
| IRQ優先度 | 現状維持 |

**この案ではCubeMXの追加修正は不要。** TRGO/SlaveやCCRをランタイムで隠れて変更しない。
異なる周期・クロック・モードなら位相合わせ付きFOC開始を拒否する。

## 狙う位相と所要時間

目標はTIM8 CNT=1120（7 µs）付近でTIM1を頂点から始動すること。
するとFOC頂点基準ではCS Lowが約33 µs、SPI送信が約34 µsとなる。
TIM8のCCRを変更せず、TIM1側の開始時刻で同じ送信位置を作る。

```text
FOC頂点基準       0          約33   34   37.2     43   約45.5   50 µs
TIM1/ADC          |------処理------|
CS                            Low---------------High
SPI                                 |3.2 µs|
受信IRQ/公開                                 |----------|
次のFOC頂点                                                     |
```

CS HighはTIM8自身の折り返しなので、FOC頂点の約43 µs後になる。
CSをHighへ戻すタイミングとCPUで角度を公開するタイミングは同じではない。
実測のRX処理約8.3 µsを足すと、公開は37.2+8.3≒45.5 µs、次の頂点まで約4.5 µs。
これは開始候補の見積もりであって、最悪時間の保証ではない。
詳細8点の計測フックあり/なしを混ぜず、それぞれADC終了と受信開始の余裕も測る。

開始受付窓の候補はCNT=1120..1199（7.0..7.5 µs）。
開始レジスタ操作後にもCNTを読み、開始を挟む読み取りが1120..1279（7.0..8.0 µs）内に
収まったことを確認する。したがってSPI開始はFOC頂点から約33..34 µs。
この1 µs幅は受け入れ目標であり、実装した命令列の所要時間を測って確定する。

1周期前の要求への応答を使う構造は残る。
通常角度のADC入口でのageの見積もりは `2*50 - (33..34) + ADC入口遅延`、
すなわち約66..67 µs＋ADC入口遅延。センサー内部遅延を含む物理的な角度年齢ではない。
旧方式の23 µsには戻らない。診断フレームの最大ageも別に測る。

## 開始手順

対象はFOC（電圧/電流モード）の本運転開始のみ。ブートストラップ、校正、手動PWM、
六ステップ、ADC単独の開始経路には待ちを追加しない。

1. 現行の開始前検査とブートストラップを完了する。
2. モーター出力OFF、TIM1 CEN=0で3相50%を設定し、既存のResetTimerPhaseで
   頂点・下降開始・RCR位相を準備する。TIM8のCNT/UG/DMAには触れない。
3. 現在の長い排他区間の外でTIM8の受付窓を待つ。
   **待ち中はIRQを許可する。50 µs待つ間ずっと割り込み禁止にしてはいけない。**
   呼び出しはmain限定、入場時PRIMASK=0を必須とする。
4. 窓に入ったら短い排他区間でTIM8の位相・通信状態、FOCの異常ラッチ、nFAULT、
   TIM1停止/出力OFFを再確認する。窓を逃していたら排他解除して次周期を待つ。
5. 現行順序でCCER→CEN→MOEを有効化し、直後のTIM8 CNTで開始位置を検証する。
   状態変数の公開まで排他内で完了する。位相範囲外なら即時出力OFFとして開始失敗にする。
6. 既存のCurrentSense_BeginControlを呼び、FOCは従来どおりゼロ電圧で
   新しい角度・ADCの到着を待ってからランプ開始する。

待機期限候補はDWT差分で200 µs（4周期）。受信IRQを優先し、窓を逃しても期限内でだけ再試行する。
期限超過、TIM8停止、通信異常、開始前検査不成立ならPWMを有効化せずHAL_ERROR/HAL_TIMEOUTを返す。
既存の開始失敗経路でFOCを停止する。割り込み禁止中にHALやprintf、待機ループを呼ばない。
ISRで異常停止が入った後にmainが出力を再有効化しないよう、最終判定では
`FocVoltage_IsActive()`だけでなく、異常ラッチと開始待ち状態も確認する。

## FWの変更範囲

| 場所 | 変更内容 |
|---|---|
| as5047p.c/.h | 通信が有効なときTIM8 CNTを返す小さな読み取りAPI。タイマー/DMA設定は変更しない |
| motor_control.c | StartAtMidpointのFOC本運転分岐だけに、期限付き位相待ちと短い開始処理を追加 |
| foc_voltage.c/.h | 開始待ち中かつfaultなしを最終確認する読み取り関数。故障ラッチを消す操作は追加しない |
| status/試験 | 開始前後の位相、待機時間、公開から次のFOC頂点までの余裕を記録 |

API名の案は`AS5047P_GetTimerPhase(uint32_t *count)`と`FocVoltage_CanEnablePwm()`。
開始窓の判定とモーター出力の操作はmotor_control側が所有し、エンコーダードライバーに出力操作を渡さない。
GetTimerPhaseは通信状態と設定の前提を検証する。割り込み排他の所有者を明記して二重待機を作らない。
両APIを実装済み。最終版では開始直後だけTIM8 CNTを直接読み、再検査による観測遅延を避ける。

角度パイプライン、HT/TCの対応、`previous_launch/next_launch`、DWT要求時刻の加算は維持する。
位相合わせではエンコーダーを停止/再起動しないため、追加の初回応答破棄や診断やり直しは不要。
停止時は従来どおりTIM1を止めるだけで、TIM8は角度取得を続ける。再始動時は毎回合わせ直す。
運転中の位相ずれは運転を止めて扱い、動いているTIM1/TIM8のCNTを書き換えて補正しない。

## 実装後の検証・採用条件

まず開始処理の分岐試験で、窓の内外、CNT周回、期限超過、通信停止、異常ラッチ、
開始処理中の割り込み競合、校正/ADC単独経路への非適用を確認する。
ARMエミュレーションでロジックを試験しても、実際のタイマー進行・CS波形の証明にはならない。

実機では同じ計測構成で±0.3 V・各30秒、同方向の停止/再開も含む10回の開始と複数回のMCUリセットを行う。
その後、少なくとも10分の連続運転で位相維持を測る。現行の電流・回転数監視を維持する。
評価項目は以下。

- 開始位相が毎回指定範囲に収まること。開始操作の短い排他時間も実測する。
- TIM1位相とTIM8位相を対応付けた計測で、運転中に位相が移動しないこと。
  TIM1のDIR反転やCNT周回をまたぐ読み取りは再取得し、見かけの位相ずれを除く。
- 通常角度の公開が次のFOC頂点より少なくとも2 µs早いことを目標に、全フレームの最小余裕を計測する。
  遅延最大の統計だけでは公開とADCの前後関係は証明できない。
- 100 Hzログのage中央値/p99と、全制御周期のFOC age_maxを別に比較する。
  診断フレームで角度が更新されない周期も含め、250 µs制限は緩めない。
- エンコーダー/ADC/シリアルエラー0。FOC処理・IRQ占有時間の追加負荷を測る。

オシロが使える場合はPA15のCSとSCKを観測し、既知のTIM1位相を示す信号と比較する。
基準信号用の空き端子は基板で確認してから指定する。ソフトIRQマーカーにはIRQ待ちが含まれる。

窓を安定して捕捉できない、位相が維持できない、または必要な公開余裕を確保できない場合は
この案を採用せず、TIM1 TRGO→TIM8 Reset案へ戻る。その時点で通信切替を実装し、
CubeMXのTRGO/Slave設定をユーザーへ依頼する。
位相合わせだけで旧方式に対する鮮度とCPU負荷の釣り合いが改善しなければ、旧方式の採用も残す。
