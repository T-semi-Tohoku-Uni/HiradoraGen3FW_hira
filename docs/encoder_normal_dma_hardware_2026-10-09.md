# 通常DMA切り戻し後の実機確認（2026-10-09）

## 結論

通常DMA版を実機へ書き込み、角度取得、停止／開始、低電圧正逆FOC、低電流PI、
ADCログ、電源電圧・温度読出し、保存校正の読込みと再起動を確認した。
基本機能の復帰は確認できたが、全条件で元どおりの性能を保証する結果ではない。
電流PIの角度更新待ちと、200 Hz詳細ログ＋頻繁な状態照会時のログ取りこぼしが残る。
今回、FWソース・CubeMX設定は変更していない。コミット・pushも未実施。

## 書き込みと校正

- COM6、921600 baud、ST-LINK `0048003F3234510A37333934`。
- 実測VMは約24.2～24.3 V。以前許可された低電圧・低電流の範囲で試験した。
  電源装置の電流制限や機械的な無負荷状態そのものはソフトウェアから再確認できない。
- Release ELF SHA256：`89DDA563A07CCBD4EC59581C93647B899B19CEF8FE153542783C55C792BAF4C3`。
- 書き込みVerify成功。校正ページ0x0801F800、2048 Bは事前退避し、試験後読出しと一致。
  SHA256：`EF71DD686D933F0A3DFA59F6B6654CA0E304F246908DBFA99AEA4A7B51153ADF`。
- direction=1、offset=1.961604 rad、H2 a2=-0.053652 / b2=0.060009を保持。
  再校正やFlash保存コマンドは実行していない。H2補正有効時の実機比較は今回未実施。

## 残る制約・未解決事項

### 200 Hz詳細ログと状態照会

正逆とも転送データのタイムスタンプは対応しているが、FWログoverrunは291／290。
sample番号にも飛びがある。通信エラー0やFOC正常動作だけでログも正常とは判断できない。
100 Hzへ下げ、angle status連続照会を外した条件ではoverrun=0、sample差200で欠落なし。
周波数と照会負荷の両方を変えたため、どちらが支配的かは未分離。

ホストスクリプトの `# COMMAND ...` 注記が受信行の途中に挿入される問題も確認した。
既存 `analyze_timing_log.py` はその生ログに対してtimestamp mismatchで停止する。
今回の集計では既知の `# COMMAND` / `# STOP_REQUEST` 注記だけをメモリ上で除去し、
生ログは変更していない。除去後は全8系列のタイムスタンプが対応した。
この注記問題とFWのoverrunは別問題であり、注記を除いても200 Hzでの欠落は残る。

### 電流PIの角度更新待ち

電圧FOCでは取得できたログのangle_age中央値24 µs（23～25 µs）。
以前の通常DMA評価23～24 µsと同程度。ただし200 Hz側は欠落を含む標本。
全制御周期を監視するFOC angle_age_maxは正逆87.337／87.356 µs、100 Hz再試験105.200 µs。

0.5 A電流PIではログangle_age中央値70 µs、最大120 µs、FOC angle_age_max=233.437 µs。
ADC制御最大29.550 µs、busy_ticks=115、decode_waits=17,897がこの試験で増えた。
後続の電圧FOCでは両カウンターが増えなかった。エラー停止はないが、
PI処理とDMA応答処理のタイミングを追加確認する必要がある。
旧通常DMA版との同条件PI比較は今回実施しておらず、切り戻しによる退行とは断定できない。

高速・高電流・負荷付き、長時間耐久、6ステップ各コマンド、再校正・保存、故障注入は未検証。
次の優先事項は低電流PIでの角度更新待ちの切り分け。大きな制御変更をする前に、
ADCログ有無と起動ごとの再現性を確認する。
