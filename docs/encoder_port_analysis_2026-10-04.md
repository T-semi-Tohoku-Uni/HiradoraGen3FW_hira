# 先輩FWのエンコーダー取得方式と移植案（2026-10-04）

## 結論

TIM8のPWMでCSを生成し、タイマーの比較イベントでSPI送信DMAを起動する方式は、このFWにも移植できる見込み。
既存の `AS5047P_GetSample()` と校正・FOC・保護の接続を維持し、`as5047p.c` の転送部分を置き換える案を推奨する。
先輩FWの設定値をそのままコピーするのではなく、送信コマンド、CSタイミング、受信の鮮度監視を整える必要がある。

今回は静的解析のみ。FWソース・CubeMX設定は変更せず、ビルド・書込み・実機試験も実施していない。

## 先輩FWの動作

主な根拠は `Core/Src/main.c:74,118,140,337,882,1071` と `Core/Src/stm32g4xx_hal_msp.c:647,743,828`。

1. `uSpiTxVal=0x3FFF`、受信先は `volatile uint16_t uSpiRxVal`。
2. `MC_SPI_TransmitReceive()` が2本のDMAを長さ1で開始する。
   - TIM8_CH1要求 → 定数からSPI1のDRへ転送。
   - SPI1_RX要求 → SPI1のDRから受信変数へ転送。
3. 両方とも循環DMA。`HAL_DMA_Start()` を使い、通常の転送完了割り込みは有効化していない。
4. PA15をAF2/TIM8_CH1に割り当て、PWM1でCSを生成する。
   - PSC=0、ARR=320、CCR1=56、極性High。
   - CNT<56はCS High、比較一致でCS Low。同じ比較イベントが送信DMAを起動。
5. SPIは16 bit、Mode 1、MSB first、160 MHz/16=10 MHz。
6. 制御は最新受信変数の下位14 bitを読み、`raw / 16383 * 2π` で機械角にする。

概念的には `TIM8 → CS/PWMと送信DMA → SPI → 受信DMA → RAM → 制御処理`。
CPUによる各フレームの開始・CS操作・完了処理が不要になる点が、この方式の利点。
ただしRAMからの取得、角度換算、異常判定は別途CPUの仕事となる。

設定からの計算値（波形の実測値ではない）:

| 項目 | 値 |
|---|---:|
| CS周期 | 321 / 160 MHz = 2.00625 µs |
| フレーム頻度 | 約498.44 kHz |
| CS High | 56 / 160 MHz = 350 ns |
| CS Low | 265 / 160 MHz = 1.65625 µs |
| 16 bit転送 | 16 / 10 MHz = 1.6 µs |

## そのまま移植しない点

### 1. コマンド `0x3FFF`

AS5047Pのコマンドはbit14がRead/Write、bit15が偶数パリティ。角度レジスター0x3FFFの読み取りコマンドは `0xFFFF` となる。
先輩の `0x3FFF` はbit14=0であり、通常のAS5047P読出しとは一致しない。現行FWのコマンド生成はこの形式に合っている。
ZIPのコードだけでは、この値で先輩の実機が動いた理由は確定できない。実装部品・MOSI配線・実際に書き込まれた版・波形との照合が必要。

### 2. CSの時間余裕

AS5047PはCS下降から最初のSCK立上りまで350 ns以上、CS Highも350 ns以上、最終SCK下降からCS上昇まで半SCK周期以上を要求する。
先輩実装ではCS下降と送信DMA要求が同じイベントなので、setup時間がDMA遅延任せになる。
さらにCS Low約1.656 µsに1.6 µsの転送を収める設定では、setupとholdの必要時間を含める余裕がない。
移植時は周期を長くし、CS下降と送信開始を別の比較イベントに分ける。

上記のプロトコル・タイミング・次フレーム応答の根拠:
[ams AS5047Pデータシート、Figure 12～15](https://www.mouser.com/datasheet/2/588/AS5047P_DS000324_3_00-1843440.pdf)。

### 3. TIM側DMAのDirection

先輩は `DMA_PERIPH_TO_MEMORY` で、HALに渡す転送元が定数、転送先がSPI DR。
同梱HALの `DMA_SetConfig()` の対応ではCPAR=定数、CMAR=SPI DRとなる。長さ1のためアドレス増分が実質影響せず、単にDirection表記だけを見て動かないとは断定できない。
移植版は `DMA_MEMORY_TO_PERIPH`、CPAR=SPI DR、CMAR=送信バッファという意図に沿った構成にする。
定数1語ならMemIncを無効、コマンド列なら有効とし、リングの長さ・応答対応も合わせる。

### 4. 角度・鮮度・診断

- 角度換算は現行の `raw * 2π / 16384` を維持する。16383割りでは最大コードが2πになる。
- 連続読出しでは受信nは要求n-1に対応する。開始直後の未対応応答を捨て、診断応答を角度と誤認しない。
- 受信ワードのコピー時刻を取得時刻とすると、停止したDMAの古い値を新しい値として扱う。実際の転送進行と時刻の対応が必要。
- 静止時も正常な角度値は同じなので「rawが変わったか」は更新確認に使わない。
- パリティ、EF、DIAAGC、ERRFL、250 µsのFOC鮮度監視を維持する。
- 校正のdirection/offset、dq変換で同一サンプルを使う設計も維持する。先輩の速度予測・位相補償は今回の通信移植に混ぜない。

## 推奨する実装案

### 周辺回路

- PA15をTIM8_CH1へ変更し、CH1はCS出力専用にする。
- TIM8_CH2の内部比較イベントで送信DMAを起動する案を第一候補とする。CH2のGPIO出力は不要。
- CS下降後に少なくとも500 nsの余裕を置いてCH2比較を発生させる。CS上昇は16 bit転送とholdの後に置き、DMA競合による遅れも実測する。
- 最初は現行と同じSPI 5 MHz、フレーム周期50 µs程度（20 kHz）で検証する。慣性のあるモーター制御で必要な鮮度は計測して判断する。
- TIM8_CH2 → SPI1 DRのTX循環DMA、SPI1_RX → 受信バッファのRX循環DMAにする。
- 現行のDMA1_Channel1=UART TX、Channel2=SPI RXは維持し、Channel3をSPI TX要求からTIM8_CH2要求へ変更する案。DMAMUX設定をCubeMXで確認する。
- TIM8はモーターPWMのTIM1とは独立に起動し、停止中の手回し・起動前の校正判定にも対応する。TIM1同期は後段の最適化候補。

### 受信・公開

初期実装は少量の循環バッファと受信完了通知を使い、完了済みワードを検証して既存の `AS5047P_Sample` へ公開する。
例えば2語のRXバッファでHT/TCを用いれば、各フレームを別スロットで受けられる。ただし処理遅延でDMAが周回する場合は破棄・無効化する必要がある。
20 kHzで毎フレーム通知しても、通常時に2フレーム/取得である現行から割り込み回数を減らせる可能性がある。

CPUは送信開始・CS操作を行わず、受信検証と公開を担う。TIM8による要求時刻と前フレーム応答の対応を保持する。
遅延したISR入口のDWTをそのまま要求時刻にせず、タイマー位相・完了イベント・リング位置に基づいて保守的にageを評価する。
TCフラグは周回回数を無制限に保持しないため、割り込み遅延・上書きを検出できない状態は有効サンプルにしない。
転送異常時はタイマー要求を止めて既存の保護へ通知する。正常時のCPU負荷低減と異常時の停止監視を両立させる。

通常の送信は `0xFFFF` の連続読出しとし、既存の20 ms診断周期に合わせて診断コマンドを挿入する。
DMAが読む語を実行中に無秩序に書き換えず、未使用領域への予約または転送境界での切替を行う。応答種別は一つ前のコマンドで判定する。
ERRFL取得後・復旧後はパイプラインを再同期し、必要な診断と新しい角度が揃うまでvalidを戻さない。

後から100 kHz等へ高速化する場合は、RXリングのHT/TCでまとめて処理する案を検討する。
毎フレーム割り込みのまま高速化するとCPU負荷が増える。まとめる場合もバッファ待ち時間をageに加算する。

`AS5047P_GetSample()` の形式は維持する方針。PauseではTIM8の要求停止、SPI完了確認、DMA停止、CS Highを保証する。
Resumeでは新しい起動・診断を行い、Flash保存中の古い受信を再公開しない。
`angle status` のbusy/decode待ち等は方式に合った受信欠落・上書き・最大公開遅延の表示へ整理する。

## 実装後の確認順序

1. Debug/Releaseビルド、CubeMX再生成との整合確認。
2. モーターPWM停止で手回し。rawの連続性、方向、0/16383境界、起動直後の無効応答除外を確認。
3. CS/SCK/MOSI/MISOを測定。setup/high/hold、16クロック、送信0xFFFF、応答対応、DMA競合時の最悪値を確認。
4. 診断応答混入なし、パリティ/EF、DMA停止・SPI異常・長いISR遅延時に古い角度を有効にしないことを確認。
5. Flash保存のPause/Resume、停止中の角度取得、起動停止の繰り返しを確認。
6. 低電圧の正逆FOCで現行と比較。角度age、ADC処理時間、ログ欠落、受信上書き、エラー、保護停止を測る。

採用判断は「通信開始のCPU依存が減り、鮮度と制御締切が改善し、既存の異常検出が維持されること」。
SPI周波数やタイムアウトの緩和だけで合格とはしない。
